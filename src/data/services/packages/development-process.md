# How does the website development process work?

- **Topic:** Process and Technology
- **Source ID:** development-process
- **URL:** https://www.lst97.dev/services

This document describes the Website Packages offering: a new website built from scratch. It covers the seven-stage build process for a new project. It does not cover the Go Support Plan, which is a separate service for a website or application that already exists and runs through a different five-stage engagement. A visitor asking how support work on an existing site proceeds needs the Go Support Plan.

Website work runs through seven stages. Development does not begin until the requirements are agreed, and the website is not launched until it has been tested and reviewed.

## 1. Project Discovery

Project discovery confirms the business requirements, the website objectives, the required pages, the required functionality, the content structure, the design direction, the third-party integrations, and the deployment requirements. The agreed requirements form the project scope before development begins.

## 2. Design & Structure

The website layout, visual direction, and content structure are prepared based on the agreed project requirements. This stage establishes the overall structure of the website before full development.

## 3. Development

The website is implemented using a modern web development stack with responsive behaviour across desktop, tablet, and mobile. Development focuses on performance, accessibility, maintainability, responsive behaviour, search engine compatibility, and long-term scalability.

## 4. CMS & Integrations

Where required, the project may include configuration of a content management system, blog management, email services, analytics, contact forms, external APIs, and other agreed third-party services.

## 5. Testing

The website is tested before production launch. Testing may include responsive layout, navigation, forms, links, CMS content, common browser compatibility, basic performance checks, metadata, the sitemap, and the deployment configuration.

## 6. Review & Revisions

The completed website is provided for client review. Standard packages include two revision rounds. Revision rounds are intended for reasonable visual, content, and configuration adjustments within the original agreed project scope. Requests that substantially change the original functionality, design direction, or project requirements may require an additional quotation.

## 7. Launch

Following approval, the website is deployed to the production environment. Launch assistance includes production deployment, domain connection assistance, basic DNS configuration, production environment configuration, and final functionality checks.

These stages apply to building a new website. They do not apply to support work on an existing site or application, which begins with a consultation or review and a diagnosis rather than with project discovery.
