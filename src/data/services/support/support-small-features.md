# Can you add small features to an existing application?

- **Topic:** Support Engagements
- **Source ID:** support-small-features
- **URL:** https://www.lst97.dev/services

This document describes the Go Support Plan offering: technical help for a website or application that already exists. It covers the Small Feature Implementation engagement. It does not cover the Website Packages offering, which builds a new website from scratch, and it is not the route to a package add-on: a feature added to an existing application is priced as a support engagement here.

Small Feature Implementation is part of the standard A$100 engagement when it is a contained change. Small features can be added to an existing application without requiring a complete rebuild.

Examples include:

- contact forms
- email sending
- analytics
- basic CMS integration
- third-party API integration
- SEO metadata
- sitemap generation
- cookie consent
- simple authentication
- file uploads
- small dashboard features
- responsive improvements

Complex functionality is quoted separately.

The defining constraint is that the work fits the existing application rather than reshaping it. Adding a contact form to an application that already has a routing structure and a deployment pipeline is a small feature. Rebuilding that routing structure to accommodate it is not, and would be quoted as a migration instead.

Most of the listed examples are configuration against services the application will use anyway: an email provider, an analytics script, metadata, a sitemap. Those tend to be the fastest engagements in the plan because there is no application logic to design, only a correct configuration to add and verify.

File uploads and simple authentication are included but are the closest to the boundary of this tier, since both introduce new failure modes. They are quoted as fixed-price tasks only when the existing application already has somewhere sensible to put them.
