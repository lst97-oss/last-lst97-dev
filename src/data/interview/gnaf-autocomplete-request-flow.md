# For GNAF Autocomplete, describe the complete flow from a user typing an address to results appearing.

- **Category:** Applied Project Questions
- **Source ID:** gnaf-autocomplete-request-flow
- **URL:** https://www.lst97.dev/chat

I built this project around six months ago, so I may not remember every implementation detail, but the main challenge was handling the size of the GNAF dataset while keeping autocomplete latency very low. The dataset is roughly in the tens-of-gigabytes range, and for autocomplete I wanted queries to return in under approximately 500 milliseconds. When the user starts typing, the frontend first validates the input and waits until there is enough text to perform a meaningful search. The request is then sent to the backend search API. The backend normalises the input and applies the appropriate search strategy depending on what information is available in the query, such as postcode, suburb, street name or street number. The database has indexes and query strategies designed specifically around the different address components so that it does not need to scan the complete dataset for every keystroke. The backend ranks and limits the matching addresses and returns only a small number of relevant suggestions to the frontend. The frontend then displays those results in the autocomplete interface. Another challenge was importing the GNAF dataset itself. Because of its size, I created a custom loader that performs the data ingestion in parallel rather than inserting records sequentially. For the intended workload, including my Best Maker project and personal use, I was able to keep individual searches below approximately 500 milliseconds.
